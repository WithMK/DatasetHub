# 설비 관리 모듈

왼쪽 `설비 관리` 메뉴 → JSON 경로 입력 → `불러오기` → 설비/PC 편집 → `설정 저장`.
저장 대상은 `현재 편집 파일`에 표시됩니다. 상단 경로를 바꾸기만 해서는 저장 대상이 바뀌지 않으며, 해당 파일을 불러와야 합니다.
Collector에서도 같은 설정 파일을 선택하세요. 새 설비/PC는 자동으로 고유한 임시 ID가 지정됩니다. PC 종류 필드는 없고 PcId로 구분합니다.

- 설비 활성화, 설비/PC 추가·수정·삭제, 대소문자 무시 ID 중복 검증.
- 로그/이미지 경로 중 하나 이상 필수. 상대경로는 JSON 파일 폴더 기준이며 로컬/UNC 경로 지원.
- MachineId 변경은 저장 전 확인. 기존 이력과 archive는 삭제·이동·재연결하지 않습니다.
- 저장 전 CollectorOptions.Validate를 복제 객체에 실행합니다. 원래 JSON의 상대경로, destinationRoot 별칭, 선택 필드 및 대소문자를 보존합니다.
- 같은 폴더의 임시 파일을 Flush 후 File.Replace로 교체합니다. 설정 편집 잠금과 SHA-256 revision 비교로 앱 간/감지된 외부 편집 충돌을 차단합니다. 잠금 파일은 재사용합니다.
- 외부 편집기가 앱의 잠금 규약을 따르지 않을 경우 최종 비교 직후의 변경까지 완전하게 막을 수는 없습니다. 동시 외부 편집 대신 불러오기→수정→저장 순서를 사용하세요.
- 파일 시스템이 원자적 교체를 지원하지 않거나 쓰기 권한이 없으면 저장 실패로 표시하고 원본을 유지합니다.
- 화면 이동·다른 파일 불러오기·정상 종료 시 저장/변경 취소/현재 화면 유지 선택. 작업 중에는 편집/화면 이동/정상 종료를 보류합니다.

## 수집 중 저장 정책

기존 Collector는 수집 시작 때 설정을 메모리에 읽습니다. 진행 중인 자동 반복 세션은 그 설정을 유지합니다.
저장한 설정은 **중지 후 다음 수집 시작**에 적용됩니다. 저장 이벤트는 같은 파일을 사용하는 대기 중 Collector의 설정 검증만 갱신합니다.
텍스트/이미지 복사 알고리즘, SQLite 스키마와 archive 처리에는 변경이 없습니다.

## 연결 확인

전체 등록 PC(비활성 설비 포함)의 설정된 경로를 확인합니다. 폴더 목록 조회와 가능한 표본 파일 1바이트 읽기만 수행하며 복사·쓰기·삭제하지 않습니다.
빈 폴더/하위 폴더만 확인된 경우 파일 읽기 권한까지 검증되지 않았음을 표시합니다. 성공은 전체 하위 파일의 권한이나 향후 연결까지 보장하지 않습니다.
10초 UI 대기 제한, 동시에 최대 4개 OS 확인, 같은 경로의 진행 중 호출을 재사용합니다. Windows SMB 호출 자체는 강제 취소할 수 없습니다.
검사 결과는 각 PC 행에 표시하며, 한 경로 오류가 다른 경로 결과를 중단하지 않습니다. 편집 중인 경로도 저장 없이 검사할 수 있습니다.

## 구조와 검증

- Core: EquipmentDocument, IEquipmentConfigurationService, 경로 확인/확인 대화상자/종료 가드 계약, 설정 저장 이벤트.
- Infrastructure: 기존 CollectorOptions를 이용한 검증, JSON 파일 저장, Windows 경로 접근 서비스.
- Modules.Equipment: View, ViewModel, 편집 Model, 독립 Prism Module. Collector 모듈 참조 없음.
- Desktop: DI/정적 모듈 등록 및 공통 비동기 종료 가드. Shell 업무 코드 변경 없음.
- 테스트: CRUD, 중복, 상대경로·기존 JSON, 원자적 교체 실패/충돌, 로컬·실제 UNC 확인, 미저장 가드, 저장 후 엔진 실행과 기존 회귀 테스트.

현장 PC의 계정/SMB ACL, 장시간 네트워크 장애와 화면 배치는 현장 검증 대상입니다.
