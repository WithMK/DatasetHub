# 1차 구현 범위: 원본 파일 수집

> 2026-10-26 범위 조정: 첫 구현은 표준 `.log` 파일 수집·검증·SQLite 파일 이력에 한정합니다. 아래 파싱·이벤트 등록은 후속 설계이며 이번 구현에 포함하지 않습니다. 개발환경은 C#/.NET 10이며 현재 수동 콘솔부터 구현합니다. 상세 상태는 [수집기 프로토타입](collector-prototype.md)을 참고하세요.

## 목적

입력 텍스트는 SEM_LOG 2.0 표준을 따르며, 업체 JSON 양식이 미정이어도 파일을 서버에 정확히 확보하고 중단 후 복구할 수 있게 합니다.

## 포함 범위

1. 설정 목록에서 설비·PC를 생성하고 추가·중지합니다. 9대/27개 고정 배열을 사용하지 않습니다.
2. 날짜·시간 폴더를 검색하고 수집 이력과 대조합니다.
3. 완료된 파일만 임시 서버 경로로 복사·검증하고 최종 확정합니다.
4. SQLite에 원본 키·경로·크기·체크섬·수집 상태·오류·시도를 기록합니다.
5. 수동 실행·기간 재점검·재시작 복구·중복 방지 기능을 제공합니다.
6. 동시 설비 수·PC당 동시 전송·속도를 제한합니다.
7. 한 PC의 실패를 기록하고 다른 PC 처리를 진행합니다.
8. 표준 로그 11필드·Timestamp·Start/End/Event를 해석하고 원본 FileId·줄 번호와 함께 등록합니다. 상세 Data 확장 규약은 실제 샘플 확인 후 추가합니다.
9. 최소한의 상태 출력과 오류 확인 방법을 제공합니다. UI 형태는 미정입니다.

## 제외 범위

업체별 Data 확장 해석·검사 JSON 파서, 제품 통합 완성, Dataset UI·모델 학습, 생산 PC 쓰기·삭제, 자동 서버 원본 삭제는 포함하지 않습니다.
검사 JSON 파서는 교체 가능한 인터페이스로 두고 실제 형식이 확인된 뒤 구현합니다. 표준 로그 기본 파서는 지금 구현할 수 있습니다.
DB는 수집 관리 테이블과 표준 로그 이벤트 테이블을 먼저 사용하며, 제품 통합용 테이블은 후속으로 추가할 수 있습니다.

## 모의 검증

생산 PC 접근 없이 로컬 폴더 3개를 원본 대체로 사용합니다. .partial 작성 후 rename 같은 모의 완료 계약을 명시합니다.
임의 확장자의 작은 합성 파일을 사용하며 실제 PNG/TIFF 디코딩 검증으로 간주하지 않습니다.

| 상황 | 기대 결과 |
|---|---|
| 동일 기간 반복 | 중복 수집·DB 행 중복 없음 |
| 복사 중 종료 | 재시작 후 부분 파일을 정상 완료로 오인하지 않음 |
| 복사 완료·DB 기록 전 종료 | 최종 파일과 이력을 재대조해 복구 |
| 원본 접근 실패 | 실패 기록, 다른 PC 계속 진행 |
| 과거 폴더에 지연 추가 | 재점검 시 발견 |
| 같은 경로 내용 변경 | 덮어쓰지 않고 충돌 표시 |
| 표준 로그 기본 파싱 | 11개 필드·밀리초 시각·상태·줄 번호가 보존되고 잘못된 행은 오류 기록 |
| 서버 공간 부족 | 오류 상태, 원본 유지 |
| 설정 1대·9대·10대 이상 | 코드 수정 없이 작업 생성, 처리량은 별도 검증 |
| 자동·수동 실행 중첩 | 같은 설비 중복 실행 차단 |

## 구현 전 환경 확인

C#을 기본 언어로 하되 .NET 버전, Windows 서비스 배포, SQLite 패키지, NuGet 반입 정책과 UI 종류를 확인합니다.
설정 예제의 수치는 잠정값이며 실장비 부하 시험을 통과한 운영값이 아닙니다.
