# 수집 모니터링

`수집 모니터링` 메뉴에서 Collector/설비 관리와 동일한 JSON 경로를 지정합니다. 5초마다 현재 설정과 SQLite 이력을 조회하며 archive 전체 탐색은 하지 않습니다.
상단은 등록 설비/PC 수, 정상/실패·지연 PC 수, 마지막 전체 실행 시작 시각입니다. 중앙에서 ID 검색/상태 필터 후 PC를 선택하면 마지막 실행의 Log/Image 실적과 최근 200건 실행·오류를 조회합니다. 요약 시각은 현지 시간, 상세 이력 시각은 UTC입니다.

## 상태의 의미

- 정상: PC 탐색 완료, 오류 없음. 파일 0개/변경 없음도 정상입니다. 이미지 안정화·로그 완료표시 대기는 별도 대기 수로 표시합니다.
- 수집 중: 시작된 PC 실행 이력과 살아 있는 DB 수집 잠금을 확인한 상태입니다. 잠금 확인은 로컬 파일 기반이며 권한 오류는 실행 여부를 확정하지 못합니다.
- 실패: 마지막 PC 실행 중 파일/경로 오류가 발생했습니다. 다른 PC 수집은 계속됩니다.
- 지연: 이 Desktop에서 자동 수집이 활성화됐고 다음 예정 시각+공통 유예(기본 2분)를 넘겨 정상 완료가 없는 PC입니다. 마지막 성공 시각과 비교하며 신규 파일 발생 여부와 무관합니다.
- 이력 없음: 실행 이력이 없는 PC. 기존 Files의 수정일을 실행 시각으로 추정하지 않습니다.
- 비활성: 설정에서 해당 설비가 비활성입니다.
- 중단: 취소되었거나 실행 도중 앱이 종료돼 완료를 확인할 수 없는 이력입니다.

앱 종료/자동 수집 중지 후에는 오래된 마지막 성공 시각만으로 지연이나 PC 장애를 판정하지 않습니다. 다른 Desktop/CLI의 스케줄 활성 여부는 공유하지 않습니다.
현재 설정의 대상 경로를 바꿔도 같은 MachineId/PcId의 과거 이력은 유지됩니다. 새 경로에 대한 정상 확인은 다음 실행 결과로 판단하세요.

## 실행 이력과 호환성

기존 Files/LogRows/ParseState/ScanErrors를 보존합니다. 기존 수집 잠금을 획득한 뒤 트랜잭션으로 CollectionRuns, SourceCollectionRuns 및 조회 인덱스를 생성하고 ScanErrors에 nullable RunId/Operation을 추가합니다. 기존 ScanErrors 및 현재 Files에 남아 있는 Failed 오류는 실행 ID 없는 이력으로 보존됩니다. 조회만으로 DB를 생성하거나 마이그레이션하지 않습니다.
PC별 StatsJson은 실행 완료 당시의 최소 통계 스냅샷이며 파일별 본문이나 파일 목록을 중복 저장하지 않습니다. 기존 파일 실패도 ScanErrors에 추가해 재시도 후 사라지지 않게 했습니다. 이전 버전에서 이미 덮어쓴 오류는 복원할 수 없습니다.
실행 취소는 Cancelled, 비정상 종료는 다음 수집 시작 시 Interrupted로 남깁니다. 시작 전 설정/잠금/DB 열기 실패는 실행 행을 만들 수 없으며 실행 화면에 표시합니다.

실적의 신규 수집은 신규+갱신 건수입니다. 실패 수는 기존 엔진 집계에 따라 파일 및 폴더 접근 실패를 포함합니다. 전송 바이트는 검증 완료된 복사 바이트(로그 증분 포함)이며 SHA 검증용 재읽기와 실패 중 전송량은 포함하지 않습니다. 내용 동일성 확인을 위해 전체 임시 복사가 수행된 경우 바이트는 증가할 수 있습니다. 중단된 PC는 완료 통계가 없으므로 0으로 표시되며 Outcome으로 구분합니다.

## 재수집

선택 PC 또는 설비, 시작일/종료일을 지정합니다. 기존 엔진을 재사용하므로 변경 없는 파일은 건너뛰고 실패 파일은 다시 확인합니다. 강제 전체 덮어쓰기 또는 개별 실패 파일 큐는 구현하지 않습니다. 이미지 안정화 조건은 그대로 유지되므로 필요하면 다음 회차에 다시 실행합니다.
Collector 자동 실행과 모니터링 수동 실행이 겹치면 기존 archive/DB 잠금이 후발 실행을 거부합니다. 자동 스케줄을 중지한 후 수동 실행하면 충돌을 피할 수 있습니다. 설정과 원본/archive를 삭제하지 않습니다.

## 구조 / 검증

Core의 ICollectionMonitoringService와 ICollectionScheduleState를 다른 모듈에서 재사용할 수 있습니다. Infrastructure가 설정/SQLite 조회와 기존 엔진 실행을 구현하며 Modules.CollectionMonitoring에는 View/ViewModel/Prism Module만 둡니다. Shell에는 업무 코드가 없습니다.
Windows 테스트는 여러 PC, 로그/이미지 실적, 빈 탐색 성공, 실패 복구, 설정 변경, 기존 DB 마이그레이션/보존, 활성 스케줄 지연, 중지/취소/중단, 선택 재수집과 잠금, WPF Navigation 및 기존 Collector/Equipment 회귀를 확인합니다.
기간별 실적 집계, 200건을 넘는 이력 페이지 탐색, 개별 실패 파일 재수집은 후속 범위입니다. 실제 설비 SMB 성능과 장시간 운전은 현장 확인 대상입니다.
