# 계속 갱신되는 표준 로그의 주기적 복사 (시험 단계)

한 시간/하루의 `.log`가 같은 경로에서 늘어나거나 덮어써질 수 있다고 가정합니다. 수동 수집은 지정된 날짜 범위를 스캔합니다. WPF **자동 반복**을 켜면 설정 주기(1·5·10·30·60분 중 선택, 시험 기본값 5분)마다 오늘과 이전 2일을 재점검합니다. UI가 열려 있어야 반복됩니다. Windows 서비스나 서버 재시작 시 자동 시작은 아직 구현되지 않았습니다.

기본 `completionSuffix`는 빈 문자열이며 `.done`이 없어도 가져옵니다. 선택적으로 `.done` 계약을 사용하는 시험에서는 `.done`으로 설정합니다. 변경 없는 파일은 저장한 크기·수정 시각과 현재 메타데이터를 비교해 건너뜁니다. 크기가 증가하면 이전 저장본의 마지막 최대 64 KiB를 원본과 대조하고 늘어난 바이트만 복사합니다. 크기가 줄거나 기존 부분이 달라졌거나 저장본이 없으면 전체 복사로 교체합니다. 따라서 파일 중간의 과거 내용만 바뀌고 크기·수정 시각이 그대로라면 감지할 수 없습니다. 원본을 읽을 때 쓰기 공유를 허용하므로 설비의 로그 핸들을 막지 않습니다. 설비가 공유 읽기를 허용하지 않으면 접근 실패로 기록하고 다음 회차에서 재시도합니다.

전체 복사가 필요할 때에는 서버 임시 파일로 복사하고 크기·수정 시각·SHA-256을 원본과 대조합니다. 이어 쓰기 중 원본 크기·수정 시각이 달라지면 이전 크기로 되돌려 다음 회차에 재시도합니다. 확인된 최신 파일은 `destinationRoot/machineId/yyyyMMdd/원본파일명.log`에 원본과 같은 구조·이름으로 저장합니다. 내용이 바뀌면 기존 복사본을 교체하고 이전 내용은 보관하지 않습니다. 버전 보관 코드는 구현되어 있지만 현재 비활성화 상태이며 추후 옵션으로 제공할 예정입니다. 같은 machineId에 속한 여러 PC에서 같은 상대 경로를 사용하면 저장 경로 중복으로 실패 처리합니다. machineId 자체의 중복은 설정을 읽을 때 오류로 거부합니다. 복사본은 **해당 시점의 관측 결과**이지 설비 로그의 최종 완료를 뜻하지 않습니다.

`Files`에는 원본 경로별 최근 관측 해시를 기록합니다. 수집 단계에서는 로그 내용 파싱을 실행하지 않습니다. 이 버전부터 새 `.snapshots` 폴더를 만들지 않습니다. 이전 빌드에서 생성된 버전 폴더는 자동 삭제하지 않으므로 기존 데이터를 정리할 때 별도로 확인해야 합니다.

폴더 날짜로 찾기 때문에 2일보다 늦게 변경된 파일은 자동 반복 범위 밖입니다. 필요한 기간을 UI에서 수동으로 지정해 재점검하세요. 원본·서버 저장소의 장애, 공유폴더 열거 누락, 설비가 저장 후 원본을 삭제한 경우까지 완전성을 증명하지는 않습니다.
